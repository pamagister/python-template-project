# Mission Plan: Slim Web-UI Template Refactor

## 1. Objective and Desired Outcome

Turn `python-template-project` into a slim, modern reference template that keeps its
developer-facing strengths (Makefile, mkdocs + awesome-nav, README mirroring, PyPI
distribution, Linux binary, `make release`, rename job, OpenCode skills) while replacing
the heavy GPX/tkinter/`config-cli-gui` stack with:

- A self-contained, parameter-driven configuration layer (no `config-cli-gui`).
- A stdlib `argparse` CLI with `gui`, `export`, and `config` subcommands.
- A lightweight, local-first web UI served by `http.server` with Pillow as the only
  image dependency.
- An image export engine (list, thumbnail, export with format/quality/resize).
- CLI documentation generated by recursing the real argparse help tree into Markdown.

Desired outcome: `python-template-project gui` opens a compact browser UI that lists
images from a local folder as selectable tiles and exports selected images to a
configurable output root using configurable export settings. The installer is
substantially smaller, docs stay slim but complete, CI passes, docs build, and
`make release` is hardened.

## 2. Scope, Constraints, Non-Goals

### In scope

- Remove `config-cli-gui` and reimplement the needed subset in-repo.
- Remove the entire GPX/KML/SRTM example domain.
- Remove tkinter GUI; replace with a local web UI.
- Reduce runtime dependencies to `pyyaml` and `pillow` only.
- Keep: Makefile targets, mkdocs config + awesome-nav, `docs/index.md` -> `README.md`
  mirroring, Linux PyInstaller build, PyPI publish, project-wide settings,
  tag-based `make release`, rename job, skills.
- Harden `make release`.
- Consolidate/trim docs while keeping `docs/index.md` complete.
- Modernize package layout and widen `requires-python` to `>=3.11,<4.0`.

### Non-goals

- No cloud/remote deployment, no multi-user concerns.
- No native desktop GUI.
- No Windows/macOS build artifacts (Linux-only; optional cross-platform jobs removed).
- No new client-side framework, no htmx, no FastAPI.
- No changes to OpenCode skills content or mirror scripts.
- No unrelated refactors outside the template's own files.

### Constraints

- Local-only server, bind `127.0.0.1` by default.
- Web UI must work with vanilla HTML/CSS/JS.
- PyInstaller bundle must include web assets and Pillow.
- The rename job must keep working; all canonical tokens must remain sed-replaceable.
- `docs/index.md` is the source for `README.md`; never edit `README.md` directly.

## 3. Architecture and Decisions

### 3.1 Package layout (modernized)

```
src/
  main.py                         # PyInstaller entry: no args -> GUI, args -> CLI
  python_template_project/
    __init__.py
    __main__.py                   # python -m python_template_project -> CLI
    _version.py                   # generated by setuptools_scm
    cli/
      __init__.py
      __main__.py
      cli.py                      # argparse builder + main()/gui_main()
      docgen.py                   # argparse help recursion -> Markdown
    config/
      __init__.py
      config.py                   # ConfigParameter/ConfigCategory/ConfigManager + YAML I/O
      docgen.py                   # config.yaml + config.md generation
    core/
      __init__.py
      logging.py                  # file/console + in-memory ring buffer for web log view
      paths.py                    # default pictures dir, output root resolution
      images.py                   # list_images, thumbnail cache, export_images (Pillow)
    web/
      __init__.py
      __main__.py
      server.py                   # ThreadingHTTPServer, routing, static, JSON API
      assets/
        index.html
        style.css
        app.js
```

Removed: `src/__init__.py`, `src/firewall_handler.py`,
`src/python_template_project/core/base.py`, `examples/`, `tests/test_gpx.py`.

### 3.2 Configuration layer (replaces `config-cli-gui`)

- `ConfigParameter`: `name`, `value`, `help`, `type`, `choices`, `required`,
  `is_cli`, `cli_group` (subcommand name or `None` for global), `cli_flag`.
- `ConfigCategory`: `name`, ordered parameters.
- `ConfigManager`: categories, `load`/`save` (YAML via PyYAML), `get`/`set`,
  `get_cli_parameters(group)`, `get_app_name`.
- Categories:
  - `app`: `log_level`, `enable_file_logging`, `enable_console_logging`.
  - `paths`: `source_dir`, `output_root` (defaults = OS pictures dir).
  - `export`: `format` (jpg/png), `jpg_quality` (85), `reduce_resolution` (False),
    `max_long_side` (1200).
  - `server`: `host` (127.0.0.1), `port` (8765), `open_browser` (True).
- CLI-exposed params are derived from `is_cli`/`cli_group`; this keeps a single
  source of truth for config.yaml, CLI flags, and docs.
- `config.yaml` writer emits comments (`# help | type | choices`) to preserve the
  current documented style; reading uses PyYAML.

### 3.3 CLI

- `argparse` only (stdlib).
- Global: `--config`, `-v/--verbose`, `-q/--quiet`.
- Subcommands:
  - `gui`: `--host`, `--port`, `--open-browser/--no-open-browser`.
  - `export`: `--source`, `--output`, `--format`, `--quality`,
    `--reduce/--no-reduce`, `--max-side`.
  - `config`: `--show`, `--set key=value` (repeatable), `--path`.
- Entry points: `python-template-project` (CLI) and `python-template-project-gui`
  (alias for `gui`).

### 3.4 CLI documentation via recursion

- `cli/docgen.py` walks `parser._subparsers`, captures each subparser's
  `format_help()`, and emits Markdown sections (usage, options table, description).
- Output: `docs/usage/cli.md`.
- Replaces `config_cli_gui.docs.DocumentationGenerator.generate_cli_markdown_doc`.

### 3.5 Image engine (`core/images.py`)

- `list_images(dir)`: filter by common image extensions, skip hidden files/dirs.
- `thumbnail(src, cache_dir)`: Pillow + `ImageOps.exif_transpose`, cached by
  filename + size + mtime.
- `export_images(files, output_root, fmt, quality, reduce, max_side)`:
  - Creates `export-<timestamp>` under the configured output root.
  - EXIF transpose, optional longest-side resize, RGB conversion for JPEG.
  - Collision-safe filenames (`name_1.ext`, ...).
- Pillow is the only image dependency.

### 3.6 Web UI (`web/server.py` + assets)

- `ThreadingHTTPServer`, bound to `127.0.0.1` by default.
- Routes:
  - `GET /` -> `index.html`; `GET /static/<file>` -> assets.
  - `GET /api/images?path=<abs>` -> JSON tile list with thumbnail URLs.
  - `GET /api/thumb?path=<abs>` -> cached thumbnail bytes.
  - `GET /api/browse?path=<dir>` -> JSON subdirectory listing for the path browser.
  - `GET/POST /api/config` -> read/update `config.yaml`.
  - `POST /api/export` -> run export, return output dir + written files.
  - `GET /api/logs` -> recent log lines from the ring buffer.
- UI: header menu (brand, Settings, Help), path bar + server-side directory browser,
  tile grid with checkboxes, export settings panel, status/log area.
- Help menu: link to Read the Docs stable, About dialog.
- Vanilla JS only; no client framework.

### 3.7 Build and release

- PyInstaller entry `src/main.py`; bundle `web/assets` and Pillow hidden imports.
- `make build-linux` only; remove `build-win`/`build-macos` and optional workflow jobs.
- `make release` hardening:
  - Validate semver tag format and that it is greater than the latest tag.
  - Reject duplicate tags and unclean working tree (allow only HISTORY.md churn).
  - Run `make precommit` and abort on failure.
  - Commit only `HISTORY.md` before tagging.
- `make tree` uses `scripts/show_tree.py` (drop `fs-tool-cli`).

### 3.8 Documentation

- `docs/index.md`: full setup guide (template usage, rename workflow, install,
  Read the Docs, PyPI token, release), updated feature list and entry points.
- `docs/usage/cli.md` and `docs/usage/config.md`: generated.
- Keep `getting-started/*`, `develop/{ci,pypi_release,contributing}.md`;
  consolidate `develop/make_windows.md` into a short Linux-only build note or remove.
- Keep `funding/funding.md`; keep `workflows.md`.
- `scripts/update_readme.py` mirrors `docs/index.md` to `README.md`.

### 3.9 Dependencies

- Runtime: `pyyaml`, `pillow`.
- Dev: `pytest`, `pytest-mock`, `pytest-cov`, `coverage`, `mypy`, `ruff`,
  `pre-commit`, `gitchangelog`, `pyinstaller`, `deptry`.
- Docs: `mkdocs`, `mkdocs-awesome-nav`, `pygments`.
- Removed: `config-cli-gui`, `fastkml`, `gpxpy`, `lxml`, `shapely`, `srtm-py`,
  `flake8`, `black`, `isort`, `fs-tool-cli`.

## 6. Dependencies, Risks, and Open Questions

### Dependencies and ordering

- Phase 2 depends on Phase 1.
- Phase 3 depends on Phase 2.
- Phase 4 is independent of Phase 3 but required by Phase 5.
- Phase 5 depends on Phases 2 and 4.
- Phase 6 depends on all prior phases.

### Risks

- PyInstaller must collect Pillow and package data; misconfiguration can bloat or
  break the binary. Mitigate with explicit `--collect-all`/hidden imports and a
  smoke test.
- PyYAML does not preserve comments; the custom emitter must be tested for stable
  round-trips.
- Path handling must reject traversal and be cross-platform.
- Removing win/mac builds changes the release surface; confirmed as Linux-only.
- Thumbnail cache invalidation must key on mtime + size to avoid stale tiles.

### Resolved decisions

- Web UI: stdlib `http.server` + Pillow (no FastAPI/Flask).
- Path selection: server-side path field + lightweight server-side directory listing.
- Export target: configurable output root with `export-<timestamp>` subdirectory.
- Settings: editable `config.yaml` via the web UI.
- CLI scope: `gui`, `export`, `config`; docs generated by parser recursion.
- Python: `>=3.11,<4.0`; modernized layout; strays removed.
- Entry points: main CLI + `python-template-project-gui` alias.

### Open questions

- None blocking. Confirm during implementation whether `funding` stays (currently kept)
  and whether `develop/make_windows.md` is folded into CI docs (currently proposed).
